# تنفيذ تدعيم Supabase — 7 نوفمبر 2026

## النطاق
تم تنفيذ هذه المرحلة على فرع `fix/supabase-auth-sync-hardening` للمشروع المستقل Factory Manager. لم تتم إضافة أدوار صنايعي أو رئيس عمال أو مسارات تشغيل خاصة بهما.

## التغييرات على قاعدة البيانات
- إضافة schema خاصة باسم `private` ودالة `private.can_access_factory_owner(uuid)` للتحقق من ملكية المصنع وعلاقة الفريق.
- استبدال سياسات RLS المتعددة بسياسة واحدة للمستخدمين المسجلين على جداول بيانات المصنع.
- إزالة وصول `anon` إلى جداول بيانات المصنع.
- قصر قراءة ملف المستخدم على سجله، وقصر التعديل من المتصفح على `full_name` فقط.
- تعيين `is_admin=false` كقيمة افتراضية، والتحقق من صلاحية الإدارة عبر العلامة الصريحة فقط.
- تمت ترقية ملف المستخدم الحالي إلى مدير النظام لأن المشروع كان يحتوي على مستخدم Auth واحد وملف profile واحد بلا مالك آخر.

## Edge Function
تم نشر `create-employee-account` مع JWT مطلوب. الوظيفة تتحقق من المستخدم وملف المدير قبل إنشاء حساب Auth وملف profile تابع للمدير، وتمنع تعيين الحساب الجديد كمدير. كلمة المرور لا تُعرض في رسالة نجاح ولا تُخزن في الواجهة.

## ملفات التطبيق
- `js/cloud-sync.js`: إزالة منح صلاحية المدير عند فشل قراءة profile، وحفظ نسخة كاملة في `factory_state`، واستعادة النسخة الكاملة قبل fallback الجداول القديمة، وعدم الكتابة فوق بيانات محلية موجودة.
- إنشاء حسابات الموظفين صار يستدعي Edge Function بدلاً من تسجيل مستخدم من متصفح المدير.
- `js/migrate.js`: إصلاح الترحيل الوهمي؛ لا يُعلّم الترحيل مكتملاً إلا بعد رفع حالة `mgr6` فعلياً.
- `index.html`: عدم إظهار رسالة نجاح عند فشل الترحيل.
- توثيق البنية الحالية في README.
